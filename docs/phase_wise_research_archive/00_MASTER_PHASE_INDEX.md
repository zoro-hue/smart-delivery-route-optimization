### Phase 01 — Phase 1 / Foundations: Genesis & Classical Routing Foundations
* **Directory Link:** [`docs/phase_wise_research_archive/01_PHASE_GENESIS_AND_FOUNDATIONS/`](01_PHASE_GENESIS_AND_FOUNDATIONS/PHASE_SUMMARY.md)
* **Time Period:** Sept 1 – Sept 20, 2026
* **Original Git Commits:** Commits `22589ea` through `5fa3313`
* **Main Research Objective:** Establish project scope with supervisor Prof. Vishnu Prasad Verma; formulate NYC last-mile delivery problem; extract NYC OSM road networks, NYC OpenData commercial delivery zones, and TLC fleet profiles; implement baseline classical solvers (Dijkstra, A*, Clarke-Wright Savings).
* **Technical Changes:** OSM graph extraction via OSMnx (54,128 nodes, 134,814 edges); initial FastAPI + React 18 Leaflet map; Dijkstra predecessor shortest path caching; initial CVRP capacity tracking.
* **Algorithms Evaluated:** Dijkstra, A* Search, Clarke-Wright Savings, Nearest Neighbor, 2-Opt local search.
* **Big Data (Spark) Innovations:** Initial data ingestion pipeline scripts for 1,898 NYC commercial zones and 10,000 TLC vehicle records.
* **Quantum Computing Innovations:** Literature review of Farhi (2014) QAOA and Hadfield (2019) quantum alternating operator ansatz.
* **Cooperative Engine Innovations:** Conceptual foundation: identified that standalone quantum solvers cannot scale to realistic NYC networks without decomposition.
* **Key Findings:** Clarke-Wright achieved 14.8% savings over nearest neighbor; revealed that raw Dijkstra without graph contraction is too slow for real-time web routing.
* **Negative Findings & Limitations:** Zero quantum execution; memory spikes on large OSM networks without edge simplification; homogeneous vehicle capacity assumption.
* **Relationship to Next Phase:** Transitioned to Phase G / Dual-Pillar Architecture to build initial PySpark polar sweep and Qiskit QAOA subproblem formulations.
